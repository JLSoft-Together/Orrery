# core — Rust PTY core (apps/core)

PLAN-v87 step 2: `orrery-core` replaces the Node PTY host behind `CCM_CORE_PTY=rust` (default `node`). Rust does only PTY + WebSocket `/pty`; preset / env / cwd / git / MCP stay in Electron main (`apps/desktop/src/pty/broker.ts`), talking over the control channel (`packages/shared/src/ptyControl.ts`, same contract as `apps/desktop/src/pty/host.ts` in `CCM_PTY_CONTROL=stdio` mode).

## Layout

Own reader on a `F_DUPFD_CLOEXEC` copy of the master fd with `poll` 100 ms + stop flag: when the leader exits but a grandchild still holds the slave (no EOF after 200 ms), the core SIGHUPs the group and stops the reader, so the thread and fd never leak. Setup error after `spawn_command` kills + reaps the child. Signal death reports `code 0` (node-pty does the same). Type-checked with `--target aarch64-apple-darwin`; not run on a Mac yet.

Shutdown: `PtyProc::hangup` SIGHUPs every group at once and returns a `Force`; the server fires them after the shared 300 ms linger (one wait for all panes, runtime never blocked). Windows `hangup` = job terminate, `Force` no-op.
  - `ring.rs` `Ring` (WP-D): fixed 256 KiB byte ring per session (grows lazily, then circular). `snapshot()` = replay; once bytes were ever dropped it skips ≤ 3 leading UTF-8 continuation bytes (replay starts on a char boundary; mid escape sequence is allowed like Node). Byte ring, not Node's 256 K UTF-16 chars cut at 1.5×: replay length differs, tail is the same.
  - `flow.rs` (WP-D): `Gate` per session (Mutex + Condvar, used from the PTY reader thread through the hub's `Sink`): `acquire(n)` blocks while `paused` (socket backlog) unless `draining`, or while `inflight + n > INFLIGHT_MAX` (256 KiB, bounds Data waiting in the hub `Event` channel); `Credit` released on drop (after the hub handled the event). `drain()` on `PtyEvent::Draining` (sent by both backends' waiter right after the child exits: remaining output is read even if the socket is paused, so kill / exit while paused still delivers tail + `exit`). `close()` when a `Session` drops (never blocks a reader of a gone session). `Meter` per WS conn: `queued` (hub, every `Out`) / `sent` (writer after `sink.send` completes = kernel accepted, analog of `bufferedAmount`); > `PAUSE_AT` 512 KiB pauses the bound gate, < `RESUME_AT` 128 KiB resumes; both under the meter lock (no lost wakeup). `bind` moves the gate between conns (attach / replace / close unpause the old one). First binary that would push a conn over `CONN_MAX` 8 MiB unsent: the conn is marked overflowed, its meter unbound (pane not kept paused), close code **4001 `overflow`** queued, and nothing more is sent to it (no hole in the stream: the client must re-attach and gets the ring replay; renderer does not handle 4001 yet, E2/F). `Draining` deliberately does not block at `CONN_MAX`: blocking there would make the exit drain time out and drop the tail after `exit`; overflow-close covers it. No socket bound = never paused (reads into the ring). Stdin control: `Gate::with_max(CONTROL_INFLIGHT_MAX)` + `Event::Release` after each chunk. WS inbound: `Semaphore` `INBOUND_MAX` 2 MiB, permit rides in `Event::Frame`.
  - `owners.rs` (WP-D, step 3): `read_pid_table()` = `core_procs::pid_parents()` (one source; unix no longer runs `/bin/ps`). Runs in `spawn_blocking`. `TableCache`: 1.5 s TTL from scan start, one scan per burst (others wait), failed scan cached as `null` too. `owners_of` = `owners.ts ownersOf` (depth 32, self-parent / missing parent stops), `wanted_pids` = `Number.isInteger && > 0`, first 64. Keys emitted ascending (JS object order for integer keys).
  - Hub (WP-D): attach order `ready, cwd, <replay binary>, branch, exit` (= `host.ts attachTo`); attach / spawn on a conn removes it from the viewers of any other session (a killed pane's late output / `exit` never reaches the conn's new pane; Node let it through); `MAX_LIVE` 16 live known sessions → `error limit` + `removed` (checked after the conn check, before the duplicate-id check); reaper `Event::Reap` every 60 s from `server.rs`, drops exited sessions with no viewer 30 min after exit (`EXITED_TTL`, `removed` to main); clock injectable `Hub::set_clock` (tests).

Output / `exit` / `branch` go to every viewer (ring written once, last viewer gets the moved buffer); a `cwd` reply goes to the asker and, when `live_cwd` changed, to the other viewers.
    Input owner: spawner / an `own` attach when there is no owner (or it replaced the owner) becomes owner. Owner changes only on `{t:"claim"}` (round 2: no implicit claim on binary input, because xterm answers DA / CPR / OSC colour / focus / mouse queries by itself, so a passive viewer would steal the owner and the size; clients send `claim` on a real key / paste — renderer WP-7, gateway WP-6). Binary input from any viewer is still written. On claim its last size is applied to the PTY and `{t:"resized",cols,rows}` goes to every other viewer (nothing when the size is unchanged). `{t:"resize"}` stores the viewer's last size, reaches the PTY only from the owner or while there is no owner; a real change is sent as `resized` to the others. A conn still bound by `c.session` but no longer a viewer (replaced `4000` socket): input still written, resize / claim ignored. `kill` clears `c.session` of every viewer of the killed session (they stay viewers until `exit` so they still get it, and can attach / spawn again on the same socket). An `own` attach also takes input from a `view` owner (round 3: desktop remount whose old socket closed first must not leave the PTY at the phone size). Owner leaves (Closed / attaches elsewhere / replaced / overflowed) → owner = first remaining non-overflowed `own` viewer, else earliest one, its size applied + `resized`; none left → no owner. Input / claim / resize after `exit` never touch the PTY.
    Flow (round 2): one `Gate` takes holds from several meters (`GateState.holds` count; a `Meter` takes 1 hold when its backlog passes `PAUSE_AT` and drops it under `RESUME_AT`, on `bind` change or unbind; meter lock then gate lock, `unhold` notifies at 0 = no lost wakeup; `set_paused` stays as a separate manual flag). Bound meters = every `own` viewer + the owner (`rebind` after join / leave / claim, skips overflowed): a slow desktop keeps the pane paced while a claimed phone reads fast, so the desktop is never closed `4001` in normal flow; a slow owner phone also paces it. A `view` that is not the owner is unbound: slow → only it gets `4001 overflow`. `send` records an overflowed conn in `Hub.spilled` (RefCell, `send` is `&self`); the end of `handle` runs `leave_all` for each, so it leaves owner choice, binders and the reaper's viewer list at once instead of waiting for `Closed` (which may never come while its writer is stuck behind 8 MiB). `kill` from any viewer as before. Message shapes are not in `packages/shared/src/pty.ts` yet (renderer handles `resized` in WP-7).

## Decisions (WP-C)

- Never sends `pid`: both backends know the pid at spawn (ConPTY `dwProcessId`, std `Child::id`). `CoreToMain::Pid` stays for the contract.
- Duplicate `resolved.id` already live → `error spawn` without `removed` (Node would overwrite and orphan the old pane).
- Pending resolves are answered `error spawn` at shutdown instead of when main answers.
- Session jobs are `KILL_ON_JOB_CLOSE`: when a session is dropped (kill, kill-all, later the WP-D reaper) or the core exits, every process still in that job dies too, including orphans the shell left running (e.g. a GUI opened with `start`, a background server). Node only killed the tree at kill / quit through `taskkill /T` and let orphans of a naturally exited shell live. Owner-visible difference.
- Duplicate `resolved.id` refusal is intentional and kept (review round 2).
- Breakaway allowed so tools that request `CREATE_BREAKAWAY_FROM_JOB` keep working; those processes survive only a core crash (pane kill still walks the tree).

## Bounds (WP-D, done)

- `Out` and `Event` stay tokio unbounded channels but every producer is byte-credited: PTY Data (Gate inflight 256 KiB + socket pause 512/128 KiB), WS frames (2 MiB semaphore), stdin control (4 MiB). Measured: child writing 8 MiB to a non-reading client stalls at ~640 KiB, core RSS +1.1 MB, no line lost. Only `Exit`, timers, `Open` / `Closed` remain uncredited (one per session / conn).

## core-transcript (PLAN-v87 step 4, WP T1)

- `crates/core-transcript` (lib; deps `core-procs` for `lines::Lines`, `memchr`, `serde`, `serde_json`, windows-sys `Win32_System_Time`, unix `libc`): Rust port of `apps/collector/src/usage.ts` `UsageIndex`, served by `orrery-core transcript` (`serve.rs`). - Tests: unit (`tests.rs`: parse, tool names, dedupe + resume copy after delete, tail / errors / truncation; `#[ignore]` `measure_phases_over_a_corpus` with `CCM_USAGE_BENCH_DIR`), `core-bin/tests/transcript.rs` (ping, errors, scan → reset, notify → update, idle, queries, save on stdin EOF).

## core-remote-proto (v97 WP-2)

- `crates/core-remote-proto` (lib thuần Rust: không IO, không tokio, không C dep, `#![forbid(unsafe_code)]`) dùng chung cho gateway desktop và app điện thoại (FRB). `snow` 0.10 bật đúng `use-chacha20poly1305|use-blake2|use-curve25519|use-getrandom`, **không** bật `std` (feature `std` của snow kéo `ring` = C) và không `ring-resolver`.
- Hằng `PROTO = 1`, `MIN_PROTO = 1`, `prologue(proto)` = `orrery-remote/` ‖ proto u16 BE. msg1 của cả 2 bắt tay = proto u16 BE ‖ noise msg: responder đọc proto rõ trước, `< MIN_PROTO` → `ProtoTooOld`, `> PROTO` → `ProtoTooNew`, rồi dựng prologue theo proto đó (proto bị sửa thì bắt tay hỏng). Lý do: prologue chứa PROTO, nếu không có tiền tố thì client cũ chỉ ra lỗi giải mã chung, không báo được `ProtoTooOld`.
- `pair/` `Noise_XXpsk3_25519_ChaChaPoly_BLAKE2s`: `PairCode` 16 B (Zeroizing), PSK = HKDF-SHA256(ikm = code, salt `orrery-pair`, info = machineId) qua `derive_psk`. `QrPayload::encode|decode` = base64url(JSON `{v,machine,name,host?,port?,relay?,mkey,code,exp}`), max 640 ký tự, Debug không in `code`. `PairInitiator::start(local, qr, deviceId, name, now)` → msg1; `finish(msg2)` so `remote_static` với `mkey`, khác → `KeyMismatch` và không có msg3; msg3 payload `{deviceId,name}` (mã hoá có PSK, sai mã → desktop lỗi ở `PairResponder::finish`). msg1 / msg2 payload rỗng.
- `session` `Noise_IK_25519_ChaChaPoly_BLAKE2s`: `SessionInitiator::start(local, desktopPub, deviceId)` → msg1 payload `{deviceId,proto}`; `accept(local, msg1, authorize)` gọi `authorize(deviceId, remoteStatic)` sau khi giải mã (key lạ / sai key desktop → `Noise` trước khi tới callback), false → `Unauthorized`, không sinh msg2; msg2 payload `{proto}`.
- `Transport` bọc `snow::TransportState`: `seal` / `open`, max plaintext 65 519 B. `open` lỗi 1 lần → transport đóng hẳn (`Closed`) để không thành oracle; lặp / đảo thứ tự / sửa byte đều lỗi nhờ nonce đếm của snow.
- `frame`: `[kind][flags][u32 stream BE][payload]`, kind 0 json / 1 pty_out / 2 pty_in / 3 ping, bit0 = more, bit khác → `BadFrame`. `Chunker` (iterator) khúc ≤ 60 KiB, `Reassembler` theo `(kind, stream)` max 1 MiB / message (đúng 1 MiB qua), thêm max 32 stream dở + 4 MiB tổng để chặn DoS; vượt → bỏ stream dở, `TooLarge`.
- `relay`: envelope `[u16 conn BE][bytes]`, conn 0 = control JSON `{t:"open"|"close",conn}` (max 256 B, conn trong control ≠ 0). Token = base64url(deviceId ‖ exp u64 BE ‖ HMAC-SHA256(relayKey, `orrery-relay/1` ‖ machineId ‖ deviceId ‖ exp)); ghép không có độ dài vẫn an toàn vì người verify cố định machineId và exp + MAC có độ dài cố định ở cuối. `verify_token` so MAC constant-time (`hmac::verify_slice`) TRƯỚC khi xét hạn (`now >= exp` → `Expired`).
- Key: `StaticKeypair` (private trong `Zeroizing`, Debug ẩn), `RelayKey` tương tự. Public key tính qua `DefaultResolver` của snow (không thêm crate x25519).
