# core — Rust PTY core (apps/core)

PLAN-v87 step 2: `orrery-core` replaces the Node PTY host behind `CCM_CORE_PTY=rust` (default `node`). Rust does only PTY + WebSocket `/pty`; preset / env / cwd / git / MCP stay in Electron main (`apps/desktop/src/pty/broker.ts`), talking over the control channel (`packages/shared/src/ptyControl.ts`, same contract as `apps/desktop/src/pty/host.ts` in `CCM_PTY_CONTROL=stdio` mode).

## Layout

- `apps/core/Cargo.toml` (workspace, release: thin LTO, `panic = "abort"`, strip), `rust-toolchain.toml` (stable), `Cargo.lock` (always `--locked`).
- `crates/core-bin` (bin `orrery-core`): `main.rs` = `orrery-core procs` → `core_procs::serve::run()`, else `core_pty::server::run()`.
- `crates/core-procs` (lib, PLAN-v87 step 3 WP-P1; no new third-party crate: `windows-sys` / `libc` / `serde` already in the lock): `table()` / `usage(pids)` / `cmdline(pids)` / `ports()` behind `sys` (`win/` · `mac.rs` · `linux.rs` · `other.rs` = None). Data = the former koffi `win-procs.ts` / `ports.ts` (removed in P4) 1:1: Windows Toolhelp32 + `OpenProcess(QUERY_LIMITED)` → `GetProcessTimes` (start read after the snapshot, same as the old koffi path: a pid reused in between gets the new start — kept on purpose; start only for pid > 4, `startRaw` = FILETIME decimal, `startMs` = `ft/10000 - 11644473600000`), `K32GetProcessMemoryInfo` EX (`workingSet`, `privateBytes`), `cpuMs` = (kernel+user)/10000 as float, `NtQueryInformationProcess(60)` (1 KiB then the asked size, max 1 MiB, UNICODE_STRING checked), `GetExtendedTcpTable` v4 + v6 (4 attempts, +4096 slack, all states, port 0 dropped). macOS `sysctl(CTL_KERN, KERN_PROC, KERN_PROC_ALL)` like `ps` (`kinfo.rs` parses 648-byte `kinfo_proc` by offset: `p_starttime` 0, `p_pid` 40, `p_comm` 243, `e_ppid` 560; sees root / other users' processes, `PROC_PIDTBSDINFO` did not), name = basename of `proc_pidpath` else `p_comm`, `PROC_PIDTASKINFO` resident + mach ticks × own `mach_timebase_info`, `KERN_PROCARGS2` → `args::parse_procargs2`), ports `lsof -nP -iTCP -sTCP:LISTEN,ESTABLISHED -F pnT` deadline 15 s (exit 1 with output accepted). Linux `/proc` (`procfs.rs` pure parsers: stat, btime, `/proc/net/tcp{,6}` + fd `socket:[inode]` → pid). Unix `startRaw` = `ps -o lstart=` with `LC_ALL=C TZ=UTC` (`start::lstart`, day padded `Mon Nov  9 …`), `startMs` = seconds × 1000; unix `privateBytes` null. `pid_parents()` = pid → ppid only (Windows Toolhelp without opening processes, macOS kinfo_proc, Linux stat) for owners. `deadline::run_with_deadline` (moved from owners.rs). `lines.rs` NDJSON reader (1 MiB line max, rest skipped, CR stripped, blank skipped). `serve.rs`: request = object with number / string `id` (else dropped), ops `ping` / `table` / `usage` / `cmdline` / `ports`, errors `op` / `pids` (not array, > 4096) / `scan`; pids deduped, non-positive / non-integer skipped; `ports` on its own worker thread (slow lsof never blocks table), all `ports` waiting in its queue share one scan (`next_batch` + `ports_replies`), others answered in order on the main thread; stdin EOF → join worker → exit 0. Contract = `.planning/PLAN-v87-step3-core-procs.md` §2.
- `crates/core-pty` (lib):
  - `control.rs`: `MainToCore` / `CoreToMain` mirror of `ptyControl.ts`, parsed by hand from `serde_json::Value` so the rules match `parseMainToCore` (unknown / invalid line = `None`, id 1..128 chars, `resolved ok:false` only with a `PTY_SPAWN_ERRORS` kind). `LineSplitter` = `NdjsonReader` (1 MiB line max, skip the rest of an oversize line, strip `\r`, skip blank). serde_json `preserve_order` keeps `resolved.env` in main's order (last duplicate wins in `session::dedupe_env`). Tests read `apps/desktop/test/fixtures/pty-control.json`.
  - `server.rs` `run()`: Windows `jobs::windows::adopt_self()` first; std thread reads stdin (EOF → `Event::StdinEof`), std thread writes stdout lines; tokio `current_thread`. Pre-init: lines before `init` are ignored (one log line), like `host.ts`; EOF before init → exit 0. Binds `127.0.0.1:0`, prints `listening`, then one select loop: accept → `ws::serve` task (accept error → sleep 50 ms), `Event` → `Hub::handle`. After shutdown it keeps handling events `SHUTDOWN_LINGER` 300 ms (late `resolved` → `removed`, like the Node host), then `Hub::force_kill` (unix: SIGKILL every pane group still alive), exits 0.
  - `hub/` `Hub` (split 2026-11-09, no behaviour change: `mod.rs` types + `handle` / `send`, `from_main.rs` main messages + census / kill / reap / PTY events, `spawn.rs` resolve / attach / settle / request_spawn, `frames.rs` WS frames + owners, `tests.rs`): single owner of all state (sessions by internal key, `ids` id → key for live-known ones, conns, `resolving`, `cwd_waits`, `wt_waits`). Mirrors `host.ts` message by message: spawn queue (`FrameQueue` 4 MB, binary droppable, log `pty input dropped while spawning: N frames over 4194304 bytes`), resolve timeout 15 s (`RESOLVE_TIMEOUT_MS`, tokio timer → `Event::ResolveTimeout`), attach order `ready, cwd, branch, exit`, replaced socket closed `4000 replaced`, kill by id from any socket, `kill` without id = attached one, PTY data after a session's `exit` is dropped (never output after `exit`); killed session stays (`known = false`) until its exit so the attached socket still gets `exit` but main gets no `exited`. `cwd` / `wt.*` relayed with rids `c<n>` / `w<n>` / `r<n>`. `census` implemented (rows sorted by spawn order). `owners`: `{}` when no wanted pid or no live session, else process-table walk (see `owners.rs`), `null` = scan failed.
  - `ws.rs`: `accept_hdr_async_with_config`, 1 MiB max message / frame. Handshake times out after 5 s (silent sockets dropped). Handshake: path `/pty` (else 400), Host `127.0.0.1:<digits>`, Origin in `init.origins`, first offered `ccm.pty.<token>` with constant-time compare (`subtle`) — any miss = 403 before upgrade (Node's `ws` answers 401; no client reads the code). Server echoes the chosen protocol. Per conn: reader → `Event::Frame`, writer drains an unbounded `Out` channel and coalesces consecutive binary chunks (≤ 1 MiB) into one frame = leading-edge flush (no 8 ms timer). Backpressure is WP-D.
  - `session.rs`: `SpawnSpec`, `PtyEvent`, `PtyProc` (`spawn` checks `cwd` `is_dir` → else `error spawn`), `WriteQueue` (writer thread, 4 MB max, overflow dropped + logged once per session), `start_reader` (64 KB reads, stamps last-data time), `clamp_dim` (= `presets.ts clampDim`), `dedupe_env` (Windows: case-insensitive, last wins at first position).
  - `pty_win.rs` (Windows): ConPTY directly through `windows-sys`, not `portable-pty` (spike: its `PSEUDOCONSOLE_INHERIT_CURSOR` makes conhost send `ESC[6n` and block the child until answered — 4/4 `cmd /c exit 3` hung 5 s — and it loads any `conpty.dll` found on the DLL search path). Flags `RESIZE_QUIRK | WIN32_INPUT_MODE` = what node-pty sends (`ESC[?9001h ESC[?1004h` at start). System conhost only. `STARTF_USESTDHANDLES` with invalid handles so a pane never inherits the core's piped stdio. `CREATE_SUSPENDED` → assign to a per-session Job → `ResumeThread` (no grandchild escapes before the job). Command line quoted exactly like node-pty `argsToCommandLine` (argv0 = `file` as given); `lpApplicationName` = `file` resolved on the pane env's PATH / PATHEXT, except `.bat` / `.cmd` (left to CreateProcess). Exit: wait process → let output settle (30 ms quiet, max 150 ms) → `ClosePseudoConsole` while the reader still drains → wait reader EOF max 200 ms → `Exit`. Exit code = `GetExitCodeProcess` u32 as i64 (NTSTATUS positive, e.g. 3221225786, like node-pty). Killed = 1.
  - `pty_unix.rs` (macOS / Linux): `portable-pty` (openpty + `setsid` + `TIOCSCTTY`, env cleared then main's env, `TERM=xterm-256color` like node-pty). Own reader on a `F_DUPFD_CLOEXEC` copy of the master fd with `poll` 100 ms + stop flag: when the leader exits but a grandchild still holds the slave (no EOF after 200 ms), the core SIGHUPs the group and stops the reader, so the thread and fd never leak. Setup error after `spawn_command` kills + reaps the child. Signal death reports `code 0` (node-pty does the same). Type-checked with `--target aarch64-apple-darwin`; not run on a Mac yet.
  - `jobs/windows.rs`: `Job` (`KILL_ON_JOB_CLOSE | BREAKAWAY_OK`), `adopt_self` (core in its own job, handle leaked on purpose: core death closes it → every pane, conhost and grandchild dies), `descendants` Toolhelp walk (kept handles, child creation time ≥ parent's to avoid pid reuse) used only when the pane has no job or `TerminateJobObject` fails (so processes that explicitly broke away survive a pane kill). `jobs/unix.rs`: pane kill = `killpg(SIGHUP)`, `SIGKILL` 2 s later from a helper thread if the group lives. Shutdown: `PtyProc::hangup` SIGHUPs every group at once and returns a `Force`; the server fires them after the shared 300 ms linger (one wait for all panes, runtime never blocked). Windows `hangup` = job terminate, `Force` no-op.
  - `ring.rs` `Ring` (WP-D): fixed 256 KiB byte ring per session (grows lazily, then circular). `snapshot()` = replay; once bytes were ever dropped it skips ≤ 3 leading UTF-8 continuation bytes (replay starts on a char boundary; mid escape sequence is allowed like Node). Byte ring, not Node's 256 K UTF-16 chars cut at 1.5×: replay length differs, tail is the same.
  - `flow.rs` (WP-D): `Gate` per session (Mutex + Condvar, used from the PTY reader thread through the hub's `Sink`): `acquire(n)` blocks while `paused` (socket backlog) unless `draining`, or while `inflight + n > INFLIGHT_MAX` (256 KiB, bounds Data waiting in the hub `Event` channel); `Credit` released on drop (after the hub handled the event). `drain()` on `PtyEvent::Draining` (sent by both backends' waiter right after the child exits: remaining output is read even if the socket is paused, so kill / exit while paused still delivers tail + `exit`). `close()` when a `Session` drops (never blocks a reader of a gone session). `Meter` per WS conn: `queued` (hub, every `Out`) / `sent` (writer after `sink.send` completes = kernel accepted, analog of `bufferedAmount`); > `PAUSE_AT` 512 KiB pauses the bound gate, < `RESUME_AT` 128 KiB resumes; both under the meter lock (no lost wakeup). `bind` moves the gate between conns (attach / replace / close unpause the old one). First binary that would push a conn over `CONN_MAX` 8 MiB unsent: the conn is marked overflowed, its meter unbound (pane not kept paused), close code **4001 `overflow`** queued, and nothing more is sent to it (no hole in the stream: the client must re-attach and gets the ring replay; renderer does not handle 4001 yet, E2/F). `Draining` deliberately does not block at `CONN_MAX`: blocking there would make the exit drain time out and drop the tail after `exit`; overflow-close covers it. No socket bound = never paused (reads into the ring). Stdin control: `Gate::with_max(CONTROL_INFLIGHT_MAX)` + `Event::Release` after each chunk. WS inbound: `Semaphore` `INBOUND_MAX` 2 MiB, permit rides in `Event::Frame`.
  - `owners.rs` (WP-D, step 3): `read_pid_table()` = `core_procs::pid_parents()` (one source; unix no longer runs `/bin/ps`). Runs in `spawn_blocking`. `TableCache`: 1.5 s TTL from scan start, one scan per burst (others wait), failed scan cached as `null` too. `owners_of` = `owners.ts ownersOf` (depth 32, self-parent / missing parent stops), `wanted_pids` = `Number.isInteger && > 0`, first 64. Keys emitted ascending (JS object order for integer keys).
  - Hub (WP-D): attach order `ready, cwd, <replay binary>, branch, exit` (= `host.ts attachTo`); attach / spawn on a conn clears `conn` of any other session still pointing at it (a killed pane's late output / `exit` never reaches the conn's new pane; Node let it through); `MAX_LIVE` 16 live known sessions → `error limit` + `removed` (checked after the conn check, before the duplicate-id check); reaper `Event::Reap` every 60 s from `server.rs`, drops exited sessions with no socket 30 min after exit (`EXITED_TTL`, `removed` to main); clock injectable `Hub::set_clock` (tests).
- Logs: one `eprintln!` line per event (`orrery-core: spawn id= preset= pid=`, `kill`, `exit`, `pty early exit: preset= code= (0x..) after=ms [killed-by-app]` identical to `presets.ts earlyExitNote`, errors with OS error numbers only). Never terminal bytes, env, token or paths.

## Decisions (WP-C)

- Never sends `pid`: both backends know the pid at spawn (ConPTY `dwProcessId`, std `Child::id`). `CoreToMain::Pid` stays for the contract.
- Duplicate `resolved.id` already live → `error spawn` without `removed` (Node would overwrite and orphan the old pane).
- Pending resolves are answered `error spawn` at shutdown instead of when main answers.
- Session jobs are `KILL_ON_JOB_CLOSE`: when a session is dropped (kill, kill-all, later the WP-D reaper) or the core exits, every process still in that job dies too, including orphans the shell left running (e.g. a GUI opened with `start`, a background server). Node only killed the tree at kill / quit through `taskkill /T` and let orphans of a naturally exited shell live. Owner-visible difference.
- Duplicate `resolved.id` refusal is intentional and kept (review round 2).
- Breakaway allowed so tools that request `CREATE_BREAKAWAY_FROM_JOB` keep working; those processes survive only a core crash (pane kill still walks the tree).

## Bounds (WP-D, done)

- `Out` and `Event` stay tokio unbounded channels but every producer is byte-credited: PTY Data (Gate inflight 256 KiB + socket pause 512/128 KiB), WS frames (2 MiB semaphore), stdin control (4 MiB). Measured: child writing 8 MiB to a non-reading client stalls at ~640 KiB, core RSS +1.1 MB, no line lost. Only `Exit`, timers, `Open` / `Closed` remain uncredited (one per session / conn).

## core-http (PLAN-v87 step 5, WP S2)

- `crates/core-http` (lib + bin `http-serve`; deps `core-store`, `tokio` (+`fs`), `tokio-tungstenite` (handshake only), `futures-util`, `httparse`, `sha2`, `subtle`, all already in the lock): Rust port of `apps/collector/src/server.ts`. No HTTP framework: `http.rs` reads the request head with `httparse` (16 KiB max, 10 s timeout) and writes `Connection: close` responses; a request with `Connection: upgrade` + `Upgrade` goes to `ws.rs`, which answers the 101 itself (`derive_accept_key`, echoes the first offered subprotocol) and wraps the socket with `WebSocketStream::from_raw_socket` (`maxPayload` 128 KiB, over = close 1009).
- `origin.rs` `host_of` / `is_allowed_origin` / `has_app_key` (`subtle` constant time) / `is_local_request` (Host in `127.0.0.1` / `localhost` / `[::1]`, Origin absent or exactly `http://<local host>:<port in ports>`); `ports` = the really bound port + `dev_origin_ports` (Node used the requested port, so port 0 never matched a real Origin).
- `server.rs` `start(Config, StoreHandle, Hooks)` → `RunningServer` (`port()`, `shutdown()`; dropping it also stops the tasks). Refuses a non-loopback `host` (`StartError::NotLoopback`); `AddrInUse` → `StartError::PortInUse`, `PORT_IN_USE_EXIT` = 3. Routes in Node order: not local → 403; `/health` (exact target, no key) → `{"ok":true,"seq":N}`; no `x-ccm-app` → 403 text; `GET /snooze?t&m&k` → 204 / 404 `no-store`; `POST /focus` (body ≤ 2048, over = connection dropped like `req.destroy()`) → `{"result":…}` 200 / 404 `rejected`; anything else static. `/api/timeline/*` is S9 (falls to static until then).
- `StoreHandle` = `Arc<Mutex<Store>>` + `Notify`: `with(|store| …)` runs the closure and wakes the flush task; `flush_loop` sleeps until `next_flush_at()` (or a wake) then `poll(now_ms())` = the 50 ms batch. Lock order is always store → clients. One listener on the store serialises each broadcast once (`Arc<str>`) into every client's unbounded channel. Connect = `flush()`, add client, push `snapshot_message()` under the same store lock (first message = snapshot including pending events); `resync` = same snapshot to that socket only; `ClientContext::reply` = `ServerMessage::direct` to the asking socket (seq −1).
- `ws.rs` per connection one task `select!`: socket read, outbox, heartbeat tick (30 s, ping; a tick with no pong since the last one = drop the socket), shutdown watch. `Hooks` (`on_client_message`, `on_client_close`, `on_client_count`, `on_focus_run` (async), `on_snooze_link`) replace the `startServer` callbacks.
- `client/` `parse_client_message(&Value) -> Option<ClientMessage>`: every branch of the Node `ws.on('message')` chain (shape + length limits counted in UTF-16 units, `sanitize*` from `packages/shared` ported in `client/validate.rs`); `ClientMessage` serialises back to the exact JSON the Node hook received (undefined fields omitted, `null` kept) so tests compare against the Node expectations. Boundary differences: `toolSpans.get.since` accepts ISO-8601 forms only (not every `Date.parse` input); `sanitizeIgnore` keeps insertion order for the first 200 projects (JS puts integer-like keys first).
- `static_files.rs`: URL-style dot-segment collapse, strict percent decode (bad = 400, NUL = 400), lexical resolve (escape = 403, a Windows `:` segment = fallback), directory → `index.html`, miss → SPA `index.html`, no index → 404 `Web UI not built. Run: npm run build`; HTML read whole with CSP, other files streamed with `content-length`. `csp.rs` `content_security_policy` (hand scanner for the `<script>` regex, CR / CRLF → LF before the sha256, own base64) + `cache_control_for` (only `assets/<name>-<8 chars>.<ext>` immutable).
- `control.rs` stdin NDJSON (1 MiB line max, same splitter rules as core-pty): `{"type":"shutdown"}` → `ControlIn::Shutdown`, stdin EOF → `ControlIn::Eof` (the owner shuts down, no orphan), other objects with a string `type` → `ControlIn::Message` (S10 wires `deviceUsed`, `diskAlert`, `agentNote`). `bin/http-serve.rs` (env `CCM_PORT` / `CCM_WEB_DIST` / `CCM_APP_KEY`, `--dev` = no key + origin 5173; prints `{"type":"listening","port":N}`; exit 3 port in use, 2 without key) exists for the process tests; S10 puts the real `orrery-core serve` in `core-bin`.
- `core-store` got one addition: `replay::replay_store` (same ops replay, returns the `Store`) for the golden test.
- Tests: unit 40; `tests/hardening.rs` (15: hardening.test ported + key / origin / heartbeat / 1009 / snooze / focus / reply / resync / loopback), `tests/static_files.rs` (4), `tests/golden.rs` (replays `monitor.ops.json` up to each Node snapshot and compares the first WS frame with the Node frame, seq included), `tests/process.rs` (5: stdin shutdown, EOF, exit 3, no key, dev). `cargo test --locked -j 4 -p core-http`.
