## WP-4a-sdk-move: SDK / emulator cũ + Docker + chuyển thư mục sang ổ khác để lại link + sửa TMPDIR macOS

- Mục tiêu (PLAN v101 Q6 + "Chuyển sang ổ khác + link"):
  1. **SDK / emulator cũ** = provider mới `group: 'dev'` trong khung `apps/desktop/src/diskClean/` (đọc `.code_index/desktop.md` mục diskClean, `.planning/wp/WP-2a-devjunk-report.md`, `.planning/wp/WP-2b-sysjunk-report.md`): Android SDK (`ANDROID_HOME` / `ANDROID_SDK_ROOT` / mặc định `%LOCALAPPDATA%\Android\Sdk`, `~/Library/Android/sdk`) `platforms/android-*` và `build-tools/*` cũ (giữ bản mới nhất + bản mà project Orrery đang biết dùng: đọc `compileSdk` / `buildToolsVersion` trong `build.gradle(.kts)` của project nếu rẻ; không chắc thì **không tick sẵn**), `system-images/*` không có AVD nào dùng, AVD (`~/.android/avd/*.avd` + `.ini`, hiện ngày dùng cuối, không tick sẵn, AVD đang chạy → khoá), Xcode `iOS DeviceSupport` cũ, iOS Simulator runtime / device không dùng (`xcrun simctl list` / `delete unavailable`: chỉ hiện + nút chạy lệnh chính thức sau confirm), Xcode `Archives` cũ hơn 90 ngày, Flutter SDK cache cũ (`bin/cache` không đụng; chỉ engine artifacts cũ nếu xác định được), Gradle `wrapper/dists/*` bản cũ (giữ bản mà project đang biết dùng theo `gradle-wrapper.properties`). Mỗi mục có lệnh khôi phục (sdkmanager / Android Studio, xcode-select...).
  2. **Docker**: provider `docker` chỉ chạy khi có `docker` CLI và daemon trả lời (timeout 3s, không thì nhóm ẩn kèm lý do). Hiện `docker system df` (images, containers dừng, volumes không dùng, build cache) theo dòng; dọn bằng **lệnh docker chính thức** sau dialog native (`docker image prune -a`, `docker container prune`, `docker volume prune`, `docker builder prune`), không xoá file trong data dir trực tiếp. Volume prune cảnh báo rõ mất dữ liệu, không tick sẵn.
  3. **Chuyển sang ổ khác + link**: hành động trên một thư mục (từ tab Duyệt / Dọn dẹp / menu chuột phải): chọn ổ đích (từ `disk.volumes`, đủ chỗ trống + 10%), kiểm thư mục không bị dùng (không có process giữ file: tên process liên quan như `java`, `gradle`, `adb`, `emulator`, `docker`, `node` đang chạy với cwd/args trong path → khoá, hoặc thử rename tạm thất bại → khoá), copy (giữ mtime, symlink bên trong copy là link, không follow) → verify (số file + tổng byte + mẫu hash vài file) → đổi tên gốc thành `.orrery-moving` → tạo junction (Windows, `mklink /J` qua `fs.symlink(target, path, 'junction')`) / symlink (macOS) → kiểm link đọc được → xoá bản `.orrery-moving` (vào Thùng rác nếu cùng ổ không được → xoá hẳn sau confirm thứ 2). Lỗi giữa chừng → rollback (đổi tên lại, xoá bản copy dở). Ghi log vào Lịch sử dọn + file `CCM_DATA_DIR/disk/moves.jsonl`; nút **Chuyển về** (ngược lại: copy về, gỡ link, đổi tên). Gợi ý sẵn các ứng viên lớn: `.gradle`, pub cache, AVD, Android SDK, Docker data (Docker data chỉ hướng dẫn qua Docker Desktop settings, không tự chuyển), npm cache. Guard canonical (`apps/desktop/src/diskMap/guard.ts`) áp cho nguồn; nguồn không được là root ổ, home, thư mục hệ thống, hay chính thư mục cài Orrery / `CCM_DATA_DIR`.
  4. **Sửa lỗi macOS TMPDIR** (từ WP-2b): guard canonical trả `system` cho `/private/var/folders/...` nên nhóm Temp trên mac luôn lỗi. Cho phép đúng TMPDIR của user (realpath của `os.tmpdir()` và con của nó) trong ngữ cảnh diskClean temp, có test.
