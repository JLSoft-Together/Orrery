## WP-v87-3-P3: test parity koffi ↔ Rust core-procs trên máy thật + E2E (Codex)
- Spec: `.planning/PLAN-v87-step3-core-procs.md` (§2 protocol, §3 WP P3, §4 không được phá). Báo cáo P1 / P2: `.planning/wp/WP-v87-3-P1-report.md`, `.planning/wp/WP-v87-3-P2-report.md`. Client TS: `apps/collector/src/coreProcs.ts`, seam `apps/collector/src/procSource.ts`; Rust: `apps/core/crates/core-procs`, server `orrery-core procs`.
- Chuẩn bị: build binary `cargo build --release --locked -j 4 -p core-bin` trong `apps/core` (PowerShell; Git Bash có `link` coreutils che `link.exe`). Binary: `apps/core/target/release/orrery-core.exe`.
- Việc:
  1. `apps/collector/test/core-procs-parity.test.ts` (chỉ chạy khi có env `CCM_CORE_BIN`, không có thì `skip` rõ ràng): trên cùng máy so koffi (`nativeProcessTable`, `nativeUsage`, `nativeCommandLine`, `winPortTable`) với client Rust (`table`, `usage`, `cmdline`, `ports`). Table: cùng pid / ppid / name / start FILETIME (± 1 µs) với ≥ 99% pid (process sinh / chết giữa 2 lần quét được bỏ). Usage: workingSet lệch ≤ 10% hoặc ≤ 2 MB, cpuMs không giảm. Cmdline: trùng chuỗi cho pid của chính test và child `node -e` tự spawn. Ports: tập (pid, port, state) LISTEN trùng nhau; có socket LISTEN do test tự mở.
  2. Đo: thời gian 1 lần quét `table` qua client (p50 / max của 50 lần) ≤ 20 ms; ghi `docs/perf/v87-step3-core-procs-win32.json`.
  3. E2E `apps/desktop/e2e/core-procs.cjs` theo mẫu các e2e có sẵn (`cdp.cjs`): dev Electron cô lập, `CCM_CORE_PROCS=rust` + `CCM_CORE_BIN`; mở Resources dialog, có danh sách process + port; session demo không bị đánh stale (dùng `scripts/demo-fixture.mjs` + `CCM_VERIFY_PROCESSES=0` nếu cần, hoặc kiểm verify bằng pid thật của một `node` tự spawn); kill một process tự spawn qua UI / IPC chạy đúng. Chạy thêm với cờ không đặt để so.
  4. Chạy lại toàn bộ `npm test -w @ccm/collector` và `npm test -w @ccm/desktop` với `CCM_CORE_PROCS=rust CCM_CORE_BIN=<exe>` và không cờ; ghi số pass / fail.
- Phạm vi file: `apps/collector/test/core-procs-parity.test.ts`, `apps/desktop/e2e/core-procs.cjs`, `docs/perf/v87-step3-core-procs-win32.json`, báo cáo. Lỗi thật trong code (không phải test) → KHÔNG sửa code, ghi vào báo cáo kèm cách tái hiện.
- Luật: không git commit/push; không viết comment trong code (mọi loại); file ≤ ~400 dòng; vitest `--maxWorkers=4`; cargo `-j 4`; tìm bằng `rg`.
- An toàn máy (bắt buộc): KHÔNG chạm app Orrery đang chạy của chủ nhân (port 4317, `%APPDATA%\Agent Monitor`, `%LOCALAPPDATA%\ccm`). Electron: `--user-data-dir` tạm, `CCM_DATA_DIR` tạm, `CCM_PORT` riêng. Dọn process chỉ theo pid tự spawn; KHÔNG `taskkill /IM` (electron.exe, node.exe, orrery-core.exe, Orrery.exe).
- Tiêu chí:
  - [ ] Parity table ≥ 99%, usage / cmdline / ports theo ngưỡng trên; số thật trong báo cáo.
  - [ ] `table` p50 / max ≤ 20 ms; file perf.
  - [ ] E2E core-procs pass với `rust` và với cờ không đặt.
  - [ ] Full test collector + desktop: số pass / fail cho cả 2 chế độ.
- Báo cáo: `.planning/wp/WP-v87-3-P3-report.md` (tiếng Việt, ≤ ~25 dòng, bảng số), dòng cuối `STATUS: DONE|PARTIAL|BLOCKED`.
