## WP-v87-5-S10: `orrery-core serve` chạy thật trong app, sau cờ `CCM_CORE`

- Spec: `.planning/PLAN-v87-step5-core-store.md` (§2, §3 dòng S10 + §3.1–§3.8, §4 cổng, §5 không được phá, §6 quyết định chủ nhân). Đọc báo cáo `.planning/wp/WP-v87-5-S{2,3,4,5,6,7,8}-report.md` (mục "việc cho S10") — danh sách nối đầy đủ ở đó.
- Mục tiêu:
  1. Subcommand `orrery-core serve` (bin `core-bin`): dựng `core-http` + `Store` + `persist` + `core-monitor` (Claude + Codex + DeepSeek) + `core-sources` (resources, sensitive thay hook S4, prompt-search) + `core-toast` (observe sau mỗi tick, timer 15 s `check_loops`, `notify.*` / presence / snooze / `/focus` / `/snooze` / diskAlert / agentNote, `drain()` ra stdout) + RPC `host.*` (S8). Đọc đúng env như `collectorEnv` (`CCM_APP_KEY`, `CCM_PORT`, `CCM_DATA_DIR`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `CODEWHALE_HOME`, `CCM_CODEX`, `CCM_DEEPSEEK`, `CCM_TOAST*`, `CCM_STALE_TTL_MIN`, `CCM_PEER_TTL_MIN`, `CCM_WEB_DIST`, `CCM_VERIFY_PROCESSES`…).
  2. Desktop: `CoreServeHost` (file mới, cạnh `CollectorHost`): spawn binary, stdin / stdout NDJSON (message main ↔ core thay `parentPort`: toast / phone / telegram / busy / resources / core-fallback / host.req…), log `collector.log`, restart max 3, boot timeout 30 s, exit 3 = port in use, kill khi main thoát (không mồ côi). Cờ `CCM_CORE=rust|node`, **mặc định `node` trong WP này**; `rust` mà `serve` không lên → tự chạy Node collector + báo 1 lần (như `noteCoreFallback`), Diagnostics có dòng `core serve: rust|node`. Main vẽ toast Windows từ message `full` (S7), macOS như hiện tại.
  3. Office: chủ nhân chốt làm sau. Chế độ `rust`: bật Office → báo rõ cần `CCM_CORE=node` (không im lặng, string i18n en + vi trong desktop / web tối thiểu).
- **Bắt buộc (phát hiện ở S2–S8):**
  - (a) `pick_folder` không được chặn thread monitor (S8 hiện đứng max ~10 phút khi dialog mở) — chạy async / thread riêng.
  - (b) `serve` không phải `--dev` mà thiếu `CCM_APP_KEY` → thoát (như collector Node); `has_app_key` key None chỉ cho `--dev`.
  - (c) `CCM_PORT` sai / `0` không được âm thầm rơi về 4317 (S5 suýt bind cổng app thật): `0` = cổng ngẫu nhiên hoặc lỗi rõ; test.
  - (d) Quét process (`core_procs::table`) đang đồng bộ trong thread monitor → không để chặn WS / store (đo: tick monitor không trễ hơn Node).
