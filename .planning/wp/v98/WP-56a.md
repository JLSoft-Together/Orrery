### Việc (thiết kế chi tiết do bạn chốt, ghi vào docs + báo cáo)
1. Nội dung (#16): hàm thuần dựng `{title, body}` theo kind (`question` / `permission` / `waiting` / `done` / `error` / `security` / `test`) và locale vi / en: title = agent · tên session (hoặc tab) · project; body = câu hỏi / quyền đang chờ (rút gọn), "Xong sau 12m", hoặc lỗi. Lọc secret (dùng lại bộ mask đang có của Rust — `mask.rs` / logic Telegram — không tự viết regex mới nếu đã có), bỏ ký tự điều khiển / bidi, cắt 120 ký tự theo grapheme / code point (không cắt giữa surrogate). Thiết bị tắt "Kèm nội dung" → giữ thông báo cố định như hiện tại. Cảnh báo `security` (WP-59) không bao giờ kèm IP / tên.
2. Web Push phía desktop (#15): khoá VAPID P-256 mỗi máy cất keychain (như `orrery-cf-token`), JWT ES256 (`aud` = origin endpoint, `exp` ≤ 12 h, `sub` cấu hình được — mặc định `mailto:` hoặc URL relay; spike lo Apple từ chối `example.com`), mã hoá RFC 8291 `aes128gcm` (ECDH P-256 + HKDF + AES-128-GCM, padding), header `TTL`, `Urgency`, `Topic` (gộp theo pane); 201 = ok, 404 / 410 = xoá subscription, 429 / 5xx = thử lại có backoff theo luật hiện có. Chọn crate đã có trong `Cargo.lock` nếu được (`p256`, `aes-gcm`, `hkdf`, `ecdsa`...), thêm mới thì ghi lý do. Test vector RFC 8291 §5 (bắt buộc pass byte-for-byte) + RFC 8292 JWT.
3. Đăng ký từ web app: lệnh phiên mới hoặc mở rộng `push.register` với `{kind: "webpush", endpoint, p256dh, auth, locale, mute, content}` (endpoint chỉ cho phép https và host push service đã biết: `web.push.apple.com`, `*.notify.windows.com`, `fcm.googleapis.com`, `updates.push.services.mozilla.com` — ghi danh sách; khác → `invalid`); `push.unregister`; desktop gửi public key VAPID cho web app (event giống `push.config`). Web app: xin quyền CHỈ khi người dùng bấm, CHỈ khi standalone trên iOS (ngoài iOS thì không cần standalone), `pushManager.subscribe({userVisibleOnly: true, applicationServerKey})`, gửi lên mỗi lần phiên ready + khi subscription đổi; SW `push` → `showNotification(title, {body, tag, data})`, `notificationclick` → mở / focus `/app/m/<m>/p/<p>`; không push khi app đang mở và hiện (#20 — desktop đã biết qua phiên; web app SW cũng bỏ nếu có client đang focus).
4. Bật / tắt nhanh (#19): chuông từng máy trên Home web app (đã có UI WP-55a) → gửi `mute` cho máy đó; desktop: nút chuông (header Settings → Điều khiển từ xa hoặc chỗ hợp lý theo design system) mở danh sách điện thoại đã ghép, bật / tắt push từng cái (lưu `devices.json`), text vi / en, trạng thái = icon + chữ + màu. Nạp skill `frontend-design:frontend-design` + `ui-ux-pro-max:ui-ux-pro-max` nếu có trước phần UI.
5. Giữ nguyên (#20): 3 nhóm chờ / xong / lỗi, 1 pane / 30 s, 30 lần / giờ / thiết bị, không push khi app đang mở, chạm mở thẳng pane, Telegram không đổi. Web Push và FCM dùng chung bộ giới hạn.
6. Ngoại lệ thứ 7 (#18): thêm vào `CLAUDE.md` đoạn Core principle ("Seventh exception (owner, 2026-11-12, v98): ...push notifications to paired phones carry agent · session · project and the pending question / permission / done time / error, secret-masked and cut to 120 characters, shown on the lock screen; per-device 'Include content' switch (on by default) ... Web Push to the web app is end-to-end encrypted per RFC 8291; FCM to Android is encrypted with the device key (WP-56b)... (docs §…)"), và docs.
7. Test: Rust (vector RFC 8291 / 8292, dựng nội dung + mask + cắt, endpoint whitelist, 404 / 410 xoá, giới hạn chung, mute theo thiết bị), web Vitest (UI chuông desktop), pwa Vitest + E2E (`npm run e2e -w @ccm/pwa`: đăng ký push với SW, nhận event `push` giả lập bằng CDP / `self.registration` để kiểm `showNotification` + click mở deep link — nếu Playwright không giả lập được push thật thì gọi handler SW trực tiếp; không vi phạm CSP). Thử thật với Edge (`channel: 'msedge'` hoặc profile tạm qua CDP như WP-50bc) gửi từ code Rust tới WNS → 201 + SW nhận — nếu dựng được; không thì ghi.
