## WP-58a: QA phần làm được trên PC — dev app thật + relay local + web app (Playwright WebKit / Chromium), không cần iPhone

- Mục tiêu: chạy web app với **desktop thật** (dev app, không phải peer giả của E2E) qua **relay chạy local** (`wrangler dev`) và qua LAN nếu có, đi hết các luồng chính, tìm lỗi tích hợp mà E2E peer giả không bắt được. Lỗi nhỏ sửa luôn; lỗi lớn ghi báo cáo.
- Spec: `.planning/PLAN-v98-ios-pwa.md` #21, WP-58; hợp đồng `docs/remote-integration.md`; các báo cáo `.planning/wp/v98/WP-5x / 61a / 61b / 62-report.md` (mục "bước QA iPhone" của từng gói = danh sách ca cần đi, trừ phần chỉ iPhone thật mới thử được).
- Code: dev app = Tauri shell `apps/shell` (đọc `CLAUDE.md` mục Commands + `.code_index/shell.md`, `.code_index/desktop.md` để biết cách chạy dev, cấu hình URL relay tuỳ chỉnh, thư mục dữ liệu riêng); relay `apps/relay` (`npx wrangler dev`, KHÔNG `wrangler login` / deploy); web app `apps/pwa` (Vite dev hoặc bản build phục vụ từ relay `/app/`).
- Phạm vi được đụng: sửa lỗi nhỏ ở `apps/pwa/**`, `apps/shell/src/remote/**`, `apps/relay/src/**` kèm test; script QA mới trong `apps/pwa/e2e/live/**` (Playwright nối desktop thật) nếu hữu ích; `docs/qa/v98/WP-58a/**`; báo cáo. Cấm: `apps/mobile/**`, `scripts/spike-v98/**`, đổi hợp đồng giao thức (ghi báo cáo thay vì đổi).
- Model: sonnet.

### Việc
1. Dựng môi trường: relay local; dev app với `CCM_DATA_DIR` riêng (thư mục tạm, không đụng dữ liệu thật của chủ nhân), trỏ relay local; bật Remote. Nếu cần Claude session thật để có pane: dùng `node scripts/demo-fixture.mjs` hoặc pane shell — KHÔNG gửi prompt nào vào Claude / Codex thật.
2. Ghép web app qua relay (QR / dán mã) — hộp duyệt native trên desktop: tự động hoá được thì làm, không thì ghi rõ bước tay. Ghép qua LAN nếu web app hỗ trợ (`ws://` / `wss://` tới 127.0.0.1 / IP LAN).
3. Đi các luồng: Home nhiều máy, Monitor A/B + chi tiết session, Workspace (mở pane shell, gõ lệnh, xterm, Ctrl/Alt, đổi tên / di chuyển / đóng + hoàn tác), viewer (Files, sửa + lưu, xung đột thật bằng cách sửa file trên đĩa, Diff, stage / commit trong repo tạm, Run nếu có cấu hình), xác nhận nguy hiểm, chế độ chỉ xem, từ chối ghép, mất kết nối relay rồi nối lại, chặn IP (WP-59) cơ bản, push Web Push tới Chromium (`Kèm nội dung` bật / tắt).
4. Mỗi lỗi: ca tái hiện, nguyên nhân, đã sửa hay chưa. Ảnh các màn chính `docs/qa/v98/WP-58a/`.
5. Kiểm lại sau sửa: `npm test -w @ccm/pwa`, `npm run typecheck -w @ccm/pwa`, `npm run e2e -w @ccm/pwa`, `cargo test -j 4 --bin orrery-shell remote::` (chạy trong `apps/shell`), relay `npx vitest run` (trong `apps/relay`) nếu đụng.

### Luật (bắt buộc)
- Không viết comment trong code (mọi loại, kể cả TODO).
- Không `git commit` / `push`. Không deploy relay, không `wrangler login`. Không build release / installer.
- Không gửi prompt vào Claude / Codex thật; không đụng dữ liệu thật của chủ nhân (`CCM_DATA_DIR` tạm). Đóng app thật đang chạy? KHÔNG — nếu app đóng gói của chủ nhân đang chạy giữ cổng 4317, dùng cổng khác (`CCM_PORT`) / dữ liệu riêng; không tắt app của chủ nhân.
- Không dùng cổng 4320–4322 cho thứ khác ngoài listener LAN của chính dev app (nếu nó cần — kiểm trước không bị chiếm).
- Tool nặng ≤ 80% CPU / RAM: `cargo -j 4`, kiểm `tasklist | grep -i cargo`. Sau `cargo build` shell: `git checkout -- apps/shell/permissions/autogenerated`. E2E pwa ghi đè ảnh `docs/qa/v98/WP-55b|56a|61a|61b/` → `git checkout --` lại.
- Bash: dùng tool Grep hoặc `rtk proxy rg`. Tắt mọi tiến trình nền (dev app, wrangler, vite) khi xong.
