## WP-64: `^C` không ngắt lệnh đang chạy trong pane shell (từ điện thoại, và cả từ desktop qua CDP trong WP-58a)

- Nguồn: `.planning/wp/v98/WP-58a-report.md` (ca `^C` với `sleep`, `ping -t`). Nghi ở ConPTY: `apps/core/crates/core-pty/src/pty_win.rs`. Đường đi bytes: web `apps/pwa/src/terminal/keys.ts` (KeyBar `^C` → byte `0x03`) → `pty.in` qua remote → `apps/shell/src/remote/**` → core-pty → ConPTY.
- Model: sonnet. Chạy song song với WP-63 (WP-63 đụng `core-remote-proto`, `apps/shell/src/remote/**` phần snapshot / relay backoff, `apps/pwa/src/remote|update` — tránh các chỗ đó; nếu lỗi nằm ở `apps/shell/src/remote` đường `pty.in` thì sửa tối thiểu và ghi lại).

### Việc
1. Tái hiện tách lớp: (a) gõ Ctrl+C thật bằng bàn phím vào pane shell trong dev app (`npm run desktop:dev` hoặc cách WP-58a dựng — dữ liệu tạm `CCM_DATA_DIR`, không đụng app thật của chủ nhân); (b) ghi `0x03` thẳng vào PTY qua core (test Rust / tool có sẵn); (c) từ web app. Xác định lớp nào làm mất Ctrl+C: byte bị biến đổi / lọc, ConPTY không chuyển thành `CTRL_C_EVENT` (vd. tạo ConPTY / process thiếu cờ, `PSEUDOCONSOLE_*`, process group, `SetConsoleCtrlHandler` kế thừa từ cha đang ignore Ctrl+C, `CREATE_NEW_PROCESS_GROUP`…), hay shell cụ thể (PowerShell / cmd / bash) xử lý khác. Nếu (a) chạy đúng mà (c) sai → lỗi ở đường remote.
2. Sửa tận gốc + test hồi quy (Rust: spawn `ping -t 127.0.0.1` hoặc `timeout`/`sleep` trong ConPTY, ghi `0x03`, process phải thoát trong ≤ 3 s).
3. Kiểm không làm hỏng pane Claude / Codex (Ctrl+C trong Claude Code vẫn phải là "huỷ"/xoá dòng như cũ — không gửi prompt nào vào Claude thật; chỉ kiểm bằng pane shell và đọc code).
