## Commands

npm workspaces (pnpm not installed on this machine). From repo root:

- `npm install` — install all workspaces
- `npm run dev` — UI work only: collector `--dev` (`127.0.0.1:4317`, no app key, no terminals) + Vite web (`127.0.0.1:5173`, proxies `/ws`). Give it its own `CCM_DATA_DIR`: it records the office timelapse into `timeline/<today>.jsonl` like the packaged app, so both would append to the same file and demo-fixture sessions would land in the real timeline
- `npm test` — Vitest in all workspaces; single file: `npm test -w @ccm/collector -- test/monitor.test.ts`
- `npm run qa` — fast gate (`scripts/qa-fast.mjs`): from `git diff`, typecheck the changed workspaces, `vitest related`, `cargo test -p <crate>` / shell, and the E2E mapped in its `E2E_MAP` (Tauri, run in parallel on separate ports); `--dry` prints the plan, `--e2e=a,b` adds files, `--no-e2e`, `--base=<ref>`
- `npm run typecheck` — `tsc` / `vue-tsc` per workspace; there is no linter, so typecheck + Vitest is the gate. Web single file: `npm test -w @ccm/web -- src/lib/themes.test.ts`
- `npm run desktop` — build web, then run the Electron app from `apps/desktop/stage` (dev); no Gradle / Java: XML Preview uses the kit pinned in `apps/layout-daemon/kit.json` (installed from Settings → Integrations → XML Preview) or a local `apps/layout-daemon/build` when one exists. - `npm run desktop:dev` — Electron app with Vite HMR for the web UI (window loads `127.0.0.1:5173`); main/collector changes still need a restart. Close a running packaged app first (single-instance lock, port 4317)
- `npm run dist` — packages for the host OS (`scripts/dist.mjs`: win32 → `dist:win`, darwin → `dist:mac`, else exit 1); no cross builds (node-pty prebuilt is host-only)
- `npm run dist:win` — build web + desktop → `apps/desktop/release/` (NSIS Setup + Portable exe)

## What this is

**Orrery** (renamed from Claude Code Monitor on 2026-10-11, then Agent Monitor → GolAIm on 2026-10-15, then GolAIm → Orrery on 2026-10-17 — an orrery is the clockwork model of planets circling a sun, like sub-agents around their main agent; userData stays pinned to the `Agent Monitor` folder; repo folder, npm package names `@ccm/*`, `appId` `dev.ccm.monitor`, data dir `ccm`, `CCM_*` env and `ccm.*` storage keys keep the old prefix on purpose so installs update in place). A local-only desktop app (Windows exe, macOS `.dmg`; no browser mode since v2.0.0) that observes running Claude Code CLI sessions (target version **2.1.289**) — plus Codex CLI runs (**0.162.0**), shown under the Claude agent that launched them — across multiple terminals and shows sessions, terminal titles, and the main-agent → sub-agent hierarchy in realtime. Since v28 an Extensions tab installs curated MCP servers / plugins into Claude Code (global or per project) only via the `claude` CLI after a native confirm (docs §11r). Since v30 a Git Log pane shows a project's history (docs §11s); since v36 its Branches toolbar can also create, fast-forward, fetch and delete branches (delete only after a native confirm). Since v59 the Explorer tree shows Atom Material file / folder icons as in IntelliJ with that JetBrains plugin (MIT, bundled by `scripts/gen-file-icons.mjs`; Settings → Appearance → File icons switches back to Simple) (`.planning/PLAN-v59-file-icons.md`). Since v58 Settings holds several GitHub accounts added by personal access token (sealed by the OS keychain, never sent back to the page); push / fetch / pull of a github.com https remote use the repo's account, picked in the Push dialog or automatically by access (`.planning/PLAN-v58-github-accounts.md`). Since v49 a Claude session in a Workspace pane can open new panes through the PTY host's MCP server `orrery`, tool `open_session` (per-pane token, prompt only prefilled, never submitted unless the agent passes `submit: true`, owner 2026-11-08), and `agent-monitor://open` does the same from outside without a confirm (owner decision; 10 links a minute, `resume=<uuid>` reopens an unfinished session, no prompt) (docs §11w). Since v50 split tabs show as groups in the rail, tabs can be named, status counts running subagents, Mission Control is a card grid, and deletes disintegrate into dust (`.planning/PLAN-v50-workspace-groups.md`). Since v52 a pane can be zoomed to fill its tab, closes can be undone (agents come back with `--resume`, dust flies back together), rows and headers show the running tool and time, pane headers collapse by container width, inactive panes can be dimmed, and Mission Control fills the screen with filter and 1–9 keys (`.planning/PLAN-v52-workspace-polish.md`). Since v60 the Monitor center can show the Habblaud pixel-art office (one room per project, a character per agent, social life, sound, day timelapse; vendored as `packages/habblaud`, MIT) (`.planning/PLAN-v60-habblaud-office.md`). Since v61 a Devices tab connects Android devices over USB / Wi-Fi (pair code, QR, mDNS discover, remembered devices with auto-connect) through the SDK's adb (`.planning/PLAN-v61-adb-devices.md`). Since v62 the file editor can auto save as VS Code `files.autoSave` (off by default; after a delay, on focus change or on window change; never over a disk conflict; with it on, closing a pane or quitting saves instead of asking) (`.planning/PLAN-v62-auto-save.md`). ## Architecture

```
apps/collector     Node.js + TS. Discovers Claude processes, session files, hook events, terminal titles
                   (codex/ for Codex runs, office/ for the Habblaud timelapse).
                   Normalizes into shared types, keeps in-memory state, serves WebSocket on 127.0.0.1 only.
apps/web           Vue 3 + TS + Vite + Tailwind + Pinia + vue-i18n + Vue Flow (Cytoscape.js fallback).
packages/shared    Event protocol + TerminalSession / Agent types shared by both apps.
apps/desktop       Electron shell (Windows + macOS): hosts collector in utilityProcess, tray, packaging.
                   Main-process features live here, not in the collector: pty/ (Workspace terminals,
                   MCP server `orrery`), devices/ (adb), extensions/, github/, layout/, preview/, run/, flutterPreview/.
apps/layout-daemon Kotlin + Gradle: warm layoutlib (Paparazzi) render daemon for the XML Layout Preview,
                   JSON-RPC 2.0 over stdio; `./gradlew test` (JDK 17–24), see its README.
packages/habblaud  Vendored Habblaud pixel-art office (MIT).
src/               Upstream source copies (escrcpy, habblaud) for reference only — not built.
```

Key cross-cutting contracts:

- **Protocol**: on connect the server sends one `snapshot`, then only incremental events (`terminal.created|updated|removed`, `agent.created|updated|removed`, `activity`). Unknown event types/fields are ignored; unknown statuses map to `unknown`.
- **Identity**: terminal/session ID is derived from process/session identity, never from the terminal title (titles change and are a tracked field).
- **Data sources**: prefer official Claude Code hooks/session files over scraping ANSI terminal output; combine with Windows process tree + file watchers only where structured data is missing. Do not guess undocumented formats — inspect the installed version first (Phase 1 deliverable: `docs/claude-code-integration.md`).
- **Frontend stores** (Pinia): `connection`, `terminals`, `agents`, `activity`, `settings`, `ui`. On disconnect keep last state visible and mark it stale; auto-reconnect.
- **Performance**: no high-frequency polling, Agent Map updates nodes incrementally (no full rebuild per event), activity list capped (~200–500), batch event bursts.
- **No database** in MVP.

## Hard rules from the plan

- Never display token counts unless reliable data exists — never invent values.
- Never expose session contents, env vars, secrets, or raw tool arguments to the frontend/logs without sanitizing. Documented exception (owner, 2026-11-11, docs §11ar): `tool.span` carries the absolute `path` + `access` (edit/read) of Edit / Write / MultiEdit / NotebookEdit / Read, nothing else from the tool input.
- No horizontal page scrolling: `overflow-x-hidden` at app level, Agent Map pans/zooms inside its own canvas, long paths truncate with tooltips.
- All UI strings via vue-i18n (`en`, `vi`); all colors via theme tokens (dark/light, persisted). Status = icon + text + color, never color alone.
- Shape tokens (v91): radius ladder `--radius-card/control/inner` plus `--ccm-card-shadow`, `--ccm-panel-*`, `--ccm-chrome-line`, `--ccm-tab-*`, `--ccm-chip-fill`, `--ccm-pane-*`, `--ccm-dim-inactive`, `--ccm-seg-*`, `--ccm-label-*`, `--ccm-gap-shell` have Apple defaults in `style.css` `:root`; themes override them in `themes.css`. Components use the utilities `ccm-panel`, `ccm-chrome-edge`, `ccm-tab-on` / `ccm-tab-rail`, `ccm-chip` + `ccm-chip-<tone>` (`statusMeta().chip`), `ccm-pane-ring` / `ccm-pane-active` / `ccm-pane-head-on` / `ccm-pane-idle`, `ccm-seg` / `ccm-seg-thumb` / `ccm-seg-on`, `ccm-label`; never branch on the theme id in a component.
- Colors: follow `.planning/COLOR-SYSTEM.md` (roles + rules): accent fill vs `accent-ink` text, status colours for lifecycle only, `success`/`warning`/`diff-*`/`agent-*`/`favorite` for other meanings, ink ladder not opacity.
- Design system: Apple (macOS HIG), spec in `.planning/AUDIT-v18-deck-reference.md` §4. Default theme since v91 (4.0.2) is **Orrery** (`orrery-light` / `orrery-dark`, soft orange accent since v92 with per-agent pane colours Claude orange / Codex purple / shell teal, flat islands; `.planning/PLAN-v91-themes-orrery-console.md`, `.planning/PLAN-v92-orrery-b-layout.md`): since v96 the dark default is **Ngân hà / Galaxy** (`galaxy`, dark only, neutral black + static stars, v95, `.planning/PLAN-v95-galaxy.md`, pair `orrery-light`) and the light default is `orrery-light`: no stored `ccm.theme` → by system scheme, and migration `4.0.2-galaxy` moves every install once (light themes → `orrery-light`, the rest → `galaxy`; `ccm.themeMigration`, `lib/themes.ts` `startTheme` mirrored by `index.html` `pick`). **Orrery dark** (`orrery-dark`) and **Console** (`console`, dark only) next to it. Apple palette (systemBlue accent, neutral greys) stays available, light + dark; v25 extra themes (Xcode, GitHub, Solarized, Monokai, Dracula, Material, One Dark, JetBrains Islands) live in `apps/web/src/themes.css` as palette-only blocks, contrast-checked by `lib/themes.test.ts`.
- Font: system stack `-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif`; mono `ui-monospace, "SF Mono", "Cascadia Mono", Menlo, Consolas, monospace`. These stay the defaults; since v27 users can pick a code font and an interface font (Settings → Text, `lib/fonts.ts`) from open-licence fonts bundled in the app (`fonts.css` + `public/fonts-LICENSES.txt`, generated by `scripts/gen-fonts.mjs`; latin / latin-ext / vietnamese, upright only). Never load fonts from the network.
- Visual style: technical developer tool — dense but calm, no gradients/decoration, with one documented exception (owner, 2026-11-11): the faint static stars of the Ngân hà theme (`--ccm-sky` token, `.ccm-sky` utility, only on the app background behind panels, header, footer and the Quỹ đạo map; panels, cards, terminals, popovers and dialogs stay opaque; no animation; Settings → Appearance → Show stars, `ccm.stars`, root `data-stars="off"`). No blur (`backdrop-filter`) anywhere (owner, 2026-11-09, GPU): chrome layers (toolbar, sidebar) use the opaque `--ccm-material` token. Popovers, menus and dialogs are opaque too. Content surfaces stay opaque.
- Before frontend work, load the skills `frontend-design:frontend-design` and `ui-ux-pro-max:ui-ux-pro-max` (`PLAN.md` calls them `/front-end-design` and `/ui-ux-promax`).

## Code index

Maintain a compact architecture index in `.code_index/` (same convention as the Android/Flutter indexers, adapted to this stack). Read it **before** any code task to find the right files; update it **after** the task.

- `_meta.md` — 1–2 line summary per change with file path + symbol reference, no long changelogs.
- `collector.md` — data sources → normalizers → state store → WebSocket broadcaster.
- `web.md` — WebSocket client → Pinia stores → components (dashboard, session cards, Agent Map, activity).
- `protocol.md` — event types and shared models in `packages/shared`, and which side emits/consumes each.
- `desktop.md` — Electron shell: boot flow, collector host, bridge install, packaging layout.

"Why"/invariant/trade-off notes belong in `.code_index/` or `.planning/`, not in source comments.
