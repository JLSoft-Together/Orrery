# Visual style, theme, font, shape token

Chuyển nguyên văn từ "Hard rules" của CLAUDE.md (v110 P4). CLAUDE.md giữ bản tóm tắt.


- Shape tokens (v91): radius ladder `--radius-card/control/inner` plus `--ccm-card-shadow`, `--ccm-panel-*`, `--ccm-chrome-line`, `--ccm-tab-*`, `--ccm-chip-fill`, `--ccm-pane-*`, `--ccm-dim-inactive`, `--ccm-seg-*`, `--ccm-label-*`, `--ccm-gap-shell` have Apple defaults in `style.css` `:root`; themes override them in `themes.css`. Components use the utilities `ccm-panel`, `ccm-chrome-edge`, `ccm-tab-on` / `ccm-tab-rail`, `ccm-chip` + `ccm-chip-<tone>` (`statusMeta().chip`), `ccm-pane-ring` / `ccm-pane-active` / `ccm-pane-head-on` / `ccm-pane-idle`, `ccm-seg` / `ccm-seg-thumb` / `ccm-seg-on`, `ccm-label`; never branch on the theme id in a component.

- Colors: follow `.planning/COLOR-SYSTEM.md` (roles + rules): accent fill vs `accent-ink` text, status colours for lifecycle only, `success`/`warning`/`diff-*`/`agent-*`/`favorite` for other meanings, ink ladder not opacity.

- Design system: Apple (macOS HIG), spec in `.planning/AUDIT-v18-deck-reference.md` §4. Default theme since v91 (4.0.2) is **Orrery** (`orrery-light` / `orrery-dark`, soft orange accent since v92 with per-agent pane colours Claude orange / Codex purple / shell teal, flat islands; `.planning/PLAN-v91-themes-orrery-console.md`, `.planning/PLAN-v92-orrery-b-layout.md`): since v96 the dark default is **Ngân hà / Galaxy** (`galaxy`, dark only, neutral black + static stars, v95, `.planning/PLAN-v95-galaxy.md`, pair `orrery-light`) and the light default is `orrery-light`: no stored `ccm.theme` → by system scheme, and `ccm.themeMigration` (`4.1-v108`) only marks the start theme as written, no stored id is forced any more (`lib/themes.ts` `startTheme` mirrored by `index.html` `pick`). **Orrery dark** (`orrery-dark`) next to it; these 3 are the kept classic themes. Since v109 Settings → Appearance shows only them and a **View all** button (`ccm.themeViewAll`, opens by itself when the current theme is an older one) reveals the older themes flagged `legacy` in `THEMES`: Apple (`light` / `dark`, no `data-theme`), Console and the v25 palettes Xcode, GitHub, Solarized, Monokai, Dracula, Material, One Dark, Islands (`.planning/wireframes/v109-themes.html`), contrast-checked by `lib/themes.test.ts`. UI next palettes since v108 (`.planning/DECISION-v108-colors.md`, `.planning/RESEARCH-v108-palettes.md`): Sương kính, Than chì, Đen trắng (`mono`, flat neutral grey), Ngân hà, Orrery, Ngẫu nhiên (`random`: mixes a new AA palette with `mauGenerate` at each launch, applied inline before first paint from `ccm.next.randomPalette`; Trộn lại / Giữ màu này) and Tự chọn; Tinh vân, Cực quang, Bình minh sương, Console were removed (`NEXT_REMOVED_PALETTES` → mist / mist / orrery / graphite).

- Font: system stack `-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif`; mono `ui-monospace, "SF Mono", "Cascadia Mono", Menlo, Consolas, monospace`. These stay the defaults; since v27 users can pick a code font and an interface font (Settings → Text, `lib/fonts.ts`) from open-licence fonts bundled in the app (`fonts.css` + `public/fonts-LICENSES.txt`, generated by `scripts/gen-fonts.mjs`; latin / latin-ext / vietnamese, upright only). Never load fonts from the network.

- Visual style: technical developer tool, dense but calm, no gradients/decoration, with one documented exception (owner, 2026-11-11): the faint static stars of the Ngân hà theme (`--ccm-sky` token, `.ccm-sky` utility, on the app background behind panels, header, footer and the Quỹ đạo map; Settings → Appearance → Show stars, `ccm.stars`, root `data-stars="off"`). Since 2026-11-13 (owner) a second sparse layer with a few bigger stars (`--ccm-sky-twinkle`, `html::after`, `.ccm-panel::before`, `.ccm-sky-well::before`) twinkles by opacity only, and meteors (`body::before/::after`, translate + opacity) cross the background, plus one meteor drawn as an SVG background layer of `.ccm-panel` / `.ccm-sky-well` (`--ccm-meteor-pane`, keyframes `ccm-meteor-pane` animate `background-position`, fixed attachment, so it passes behind panel text and terminals; repaints those surfaces only during the ~1.2 s flight every 9 s); Settings → Appearance → Star effect (`ccm.starsFx` off / twinkle (default) / meteors, root `data-stars-fx`); compositor-only animations, off under Reduce Motion. Since 2026-11-13 (owner) Settings → Appearance → Stars in panels (`ccm.starsPanels`, on by default, root `data-stars-panels="off"`) also shows them through `.ccm-panel` and terminal wells (`--ccm-sky-pane`, `.ccm-sky-well`, fixed attachment so they line up with the background; panel / well fill = canvas, xterm `allowTransparency`); off keeps panels and terminals solid. Cards, popovers and dialogs stay opaque. No blur (`backdrop-filter`) anywhere (owner, 2026-11-09, GPU): chrome layers (toolbar, sidebar) use the opaque `--ccm-material` token. Popovers, menus and dialogs are opaque too. Content surfaces stay opaque. Exception for UI next gen v102 (owner, 2026-11-15), only under `:root[data-ui='next']`: blur on chrome (rail, header, tab strip) and floating layers (menus, popovers, dialogs, Ctrl+K, Explorer drawer) through `.glass` / `.glass-pop` / `.glass-side` and `--ccm-glass-blur`, and a static mist background of radial-gradients (`--ccm-bg-image` on `html`); terminal panes, long lists and content surfaces never blur, nothing animates blur or layout, and Settings → Appearance → Reduce transparency (`ccm.next.reduceGlass`, root `data-glass="reduced"`) turns every blur off. Classic (`data-ui="classic"`) keeps the no blur / no gradient rule unchanged.
